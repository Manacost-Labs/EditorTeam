# Сервис редактуры

Принимает текст, правит его моделью, проверяет результат анализаторами и
возвращает правку — **только если она прошла затвор**. Не прошла — клиент
получает исходный текст и перечень причин отказа.

## Почему две части

```
Go: editor-gateway            Python: сайдкар
 ├─ HTTP API                   ├─ /analyze  разбор текста
 ├─ клиент модели              ├─ /validate затвор
 ├─ цикл правки        ──────► └─ /rules    правила для запроса к модели
 └─ затвор
```

Анализаторы остались на Python не по инерции. **Русской морфологии для Go
практически нет** — лучший репозиторий на GitHub имеет одну звезду. Без неё
теряется распознавание падежей и коротких имён: «Балинды» перестанет быть
Балиндой, а «Играем» снова начнёт считаться картой «Играющая на воздухе».

Go берёт то, что умеет: HTTP, конкуренцию, один бинарник, работу с провайдерами.

## Затвор — смысл сервиса

Без него это прокси к OpenRouter. Жёсткий затвор отклоняет правку, если:

| Нарушение | Что значит |
|---|---|
| `voice_flattened` | на тексте статьи голос в целом опустился ниже нижней нормы |
| `protected_lost` | пропали числа, характеристики, коды колод, **ОТК**, **возвещение** |
| `rhythm_flattened` | ритм на длинном тексте упал ниже допустимой границы |
| `text_shrunk` | текст потерял 50% и больше — вероятна утрата содержания |

Это затвор правки: точка отсчёта — исходник. В глубине **переплавка**
(`mode: переплавка`) исходник — плохой текст, и эти три относительные проверки
(`voice_flattened`, `rhythm_flattened`, `text_shrunk`) выключены. Вместо них:

| Нарушение | Что значит |
|---|---|
| `voice_below_norm` | живой голос ниже нижней границы автора (20,6 на 1000 слов) |
| `rhythm_below_norm` | разброс длин предложений ниже минимума корпуса (0,40) |
| `markers_remove_present`, `markers_above_norm` | шаблонных фраз больше, чем бывает у автора |
| `structure_missing` | обязательный раздел профиля отсутствует и не объявлен отсутствующим |
| `CLAIM_COVERAGE_LOST` | пропала карта исходника, перевёрнут совет или снято отрицание |
| `OUTLINE_INVALID`, `OUTLINE_INVENTED` | план не покрывает скелет или содержит карту/число не из исходника |

`protected_lost`, `FACTUAL_SEMANTIC_DRIFT`, `CERTAINTY_DRIFT` по claim contract и
утечки research narration действуют в обеих глубинах. Порядок разделов, тонкие
разделы, полотна, зачин и охват классов исходника возвращаются как `warnings`.

Отдельные потери живых сигналов (`voice_lost`), снижение ритма внутри
допустимого диапазона и сокращение больше 5% возвращаются как `warnings`.
Это не автоматический отказ, а обязательная редакторская проверка изменённых
мест: что именно удалено и решает ли это доказанную проблему читателя.

Модель получает конкретную причину и пробует снова, до `EDITOR_MAX_ATTEMPTS`.
После исчерпания попыток возвращается **исходный текст**: испорченный хуже
неправленого, и решать должен человек.

## Запуск

```bash
# сайдкар с анализаторами
python3 -m editorteam.server --port 8731

# сервис
export EDITOR_API_KEY=...            # ключ провайдера
export EDITOR_PROVIDER=openai        # или openrouter, cloudflare, ollama
export EDITOR_MODEL=anthropic/claude-sonnet-4.5
go run ./go/cmd/editor-gateway
```

Для Cloudflare Workers AI дополнительно нужен `EDITOR_CF_ACCOUNT_ID`.
Оба провайдера дают OpenAI-совместимый REST, поэтому клиент один.

| `EDITOR_REASONING_EFFORT` | `xhigh` | уровень рассуждения внутреннего Codex |
| `EDITOR_AGENT_TOKEN` | — | опциональный Bearer-токен входящего `/ag-ui` EditorTeam |
| `EDITOR_CF_ACCOUNT_ID` | — | только Cloudflare |

сервис принимает чужие тексты и не должен становиться местом утечки.
Тела запросов тоже не логируются.

## API

```bash
curl -X POST localhost:8080/edit -H 'Content-Type: application/json' -d '{
  "text": "…",
  "game": "hearthstone",
  "profile": "constructed-guide",
  "mode": "обычная"
}'
```

Ответ: `text`, `accepted`, `attempts` с нарушениями и предупреждениями по каждой попытке,
`changes` с построчным diff, `preserved` с тем, что прошло защитные проверки,
`saved` и `save_status` со статусом сохранения, `verdict` с замерами,
`report` с находками, `caveats`.

Редактор не перезаписывает файлы или сообщения: `saved` остаётся `false`, а
принятый результат возвращается в чат. В AG-UI этот отчёт добавляется после
текста ответа блоком «Отчёт редактора».

**Код ответа 200 и при отказе.** Непринятая правка — осмысленный результат,
а не сбой: клиент получает исходник и причины.

### Переплавка: два прохода

`"mode": "переплавка"` включает пересборку. Шлюз запрашивает у сайдкара
`/rules` с `depth` и текстом исходника: в ответ приходят скелет профиля с
назначением разделов, почерк автора из `ГОЛОС.md`, образцы абзацев из архива
(`echo.py`, STYLE ONLY) и списки маркеров фразами. Затем два прохода модели:

1. **План.** Модель возвращает JSON `{"sections": [{"id", "title", "claims"}],
   "missing_sections": [...]}`; сайдкар проверяет его на `POST /outline/validate`.
   Невалидный план повторяется один раз, потом переплавка идёт без плана.
2. **Проза.** По плану и образцам; затвор `/validate` с `depth: переплавка` и
   `declared_missing` из плана. Отказ → повтор с подсказками по виду нарушения.

В ответе появляются `depth`, `outline`, `missing_sections`, `missing_titles`.
Разделы без материала не пишутся; в AG-UI это блок «Не хватает в исходнике».
Первой строкой сообщения можно написать `переплавка` (регистр и «е/ё» не важны).
Неизвестный `mode` в `/edit` даёт 400.

В переплавке числа сверяются как факты с контекстом (число плюс класс в
предложении, только с процентом или единицей), а коды колод — склеенными через
переносы: год из колонтитула PDF и разорванный код больше не дают ложного
отказа. В CLI один вердикт даёт `editor-team check результат.md --source исходник.md`.

Сайдкар: `POST /validate` принимает `depth` и `declared_missing`; `POST /rules`
— `depth` и `text`; `POST /outline/validate` — `{outline, source, game, profile}`.

Проверка ритма блокирует правку только когда и исходник, и кандидат содержат
не менее 15 предложений и итоговый разброс падает ниже допустимой границы.
На коротких фрагментах эта метрика остаётся в отчёте, но слишком шумна для
решения. Сокращение больше 5% и минимум на 8 слов требует аудита удалений;
автоматический отказ срабатывает при экстремальном сокращении на 50% и больше.

`POST /audit` — только разбор, без модели. `GET /health` проверяет и сайдкар.

## Подключение к work.kolodahearthstone.com

В production Compose рабочей области EditorTeam поднимается двумя внутренними
сервисами: Python-анализаторами и Go-шлюзом. Шлюз обращается к
`agent-codex:4202`, поэтому использует уже настроенную ChatGPT-авторизацию и
не требует ключа внешнего провайдера. Для него заданы модель `gpt-5.6-luna` и
уровень рассуждения `xhigh` только на запросах редактора.

Сотруднику в `/agents` задаётся внутренний endpoint
`http://editor-gateway:8080/ag-ui`; этот адрес доступен только внутри сети
Compose. В текущем production Compose `EDITOR_AGENT_TOKEN` не задан, поэтому
вход защищён сетевой границей; если токен включить, клиент обязан передавать
`Authorization: Bearer`. Входящее сообщение берётся из последнего пользовательского сообщения,
игра и профиль по умолчанию — Hearthstone и `constructed-guide`. Первой строкой
можно выбрать режим `лёгкая`, `обычная`, `глубокая` или `переплавка`; если строка
не указана, используется обычная правка.

### Google Docs

Если последнее сообщение — каноническая ссылка `https://docs.google.com/document/d/<id>/edit`,
шлюз использует только выданный Боту read-only grant `read_google_document`. Сначала документ
читается через подключённый аккаунт пользователя, затем модель возвращает полный текст без
служебной ссылки и редакторский затвор сравнивает правку с этим текстом. URL больше не считается
исходным текстом, поэтому цифры из ID документа не попадают в проверку. Запись обратно в Google
Docs намеренно не выполняется: результат возвращается в чат, а отдельная операция записи требует
точного диапазона, `expectedText` и явного подтверждения.

Если grant чтения не выдан Главному редактору, ссылка завершается понятным сообщением о
необходимом доступе; вставка обычного текста продолжает работать как раньше.

Кандидат от модели не показывается по частям до проверки: шлюз поддерживает
SSE-соединение keepalive-комментариями, затем отправляет один проверенный
`TEXT_MESSAGE_CONTENT`. Так непринятый вариант не успевает попасть в интерфейс.

## Игры

`hearthstone` и `wow`. От игры зависят справочник имён, защищённые слова и нормы.

**Для WoW норм нет.** Значения заимствованы из корпуса Hearthstone того же
автора и помечены `provisional`; каждый ответ несёт оговорку. Сверка имён
отключена: `ru.wowhead.com` закрыт Cloudflare, Blizzard Game Data API требует
OAuth-ключей. Балл соответствия для WoW не калибруется вовсе.

## Дефект, найденный сквозной проверкой

Первая версия затвора **приняла** правку, вычистившую живое с 384,6 до 22,5
сигнала на 1000 слов. Причина: проверка удаления стояла после порога выборки
в 150 слов, и на коротком тексте молчала.

Удаление — факт, а не вывод из частот: если императивов было 9, а стало 0,
объём выборки тут ни при чём. Теперь такая потеря всегда видна как предупреждение,
а на тексте статьи системное падение ниже нижней нормы становится нарушением
`voice_flattened`. Тесты держат оба сценария.

# Протокол переплавки

Переплавка — не правка, а пересборка. Она нужна, когда на входе плохой текст:
ИИ-слоп, сырой черновик, канцелярит, вода. Бережная правка здесь бессильна:
закрытый список причин и лестница «оставить → починить → пересобрать»
защищают голос автора, а у слопа голоса нет, защищать нечего.

## Факт и форма

**Исходник — источник фактов, не формы.** Из него берётся всё, что должно
пережить пересборку: карты, числа, коды колод, советы «оставлять / сбрасывать»,
отрицания и условия, классы в матч-апах, позиция автора. Ни один факт не
добавляется и не теряется.

**Форма строится заново.** Образец голоса — корпус автора (`ГОЛОС.md`,
`гайды/`), а не входной текст. Структура — скелет жанра из
`config/profiles/<профиль>.yaml`: разделы в порядке профиля, у каждого своё
назначение (`purpose`).

Затвор в переплавке сравнивает результат не с исходником, а с нормой автора
(`rewrite_gate.py`) и с утверждениями исходника (`claims.py`). Относительные
проверки обычной правки (`voice_lost`, `text_shrunk`, `rhythm_flattened`)
выключены: слоп законно усыхает вдвое, а его «голос» терять не жалко.

## Источник — не шаблон структуры

Исследовательский отчёт приходит со своим оглавлением: короткий вывод, новинки,
тир-лист, коды, муллиган, популярность, матч-апы, разбор классов, методика.
Переносить этот порядок в гайд нельзя. Набор и порядок разделов берутся из
скелета профиля (`structure.py --outline <профиль>`), а отчёт даёт только факты.

Разделы результата озаглавливаются markdown-решётками: `## Муллиган`. Если
решётки есть, затвор считает заголовками только их — короткая строка
«Оставляйте Мастера брони» остаётся советом. Без решёток разделы угадываются
по коротким строкам, и затвор предупреждает `structure_no_headings`.

Форма подачи — как в 49 гайдах автора, где нет ни одной таблицы, ни одного кода
колоды в тексте и ни одного процента, повторённого в трёх абзацах:

| Правило | Норма профиля `meta-report` | Проверка |
|---|---|---|
| таблиц не больше одной | `form.tables_max: 1` | `form_tables` |
| кодов только для рекомендуемых сборок | `form.codes_max: 4` | `form_codes` |
| без оценочных букв «Положение: A−/B+» | `form.grade_labels: forbidden` | `form_grade_labels` |
| одна цифра — один раз | `form.repeated_facts_max: 0` | `form_fact_repeated`: три абзаца — отказ, два — предупреждение |

Цифра называется там, где читатель принимает решение. В других разделах на неё
ссылаются словами: «этот матч-ап и решает выбор», а не повторяют процент.
Разбор класса — связный абзац, не список «плюс / минус / итог».

## Правило честности

Раздел, для которого в исходнике нет материала, **не пишется**. Он объявляется
отсутствующим: в плане — через `missing_sections`, в проверке — через
`--declared-missing`. Затвор тогда даёт предупреждение, а не отказ, и автор
видит блок «Не хватает в исходнике». Выдумать матч-ап или муллиган хуже, чем
честно сказать, что его нет.

## Порядок работы

1. **Инвентаризация.** `claims.py исходник.md --format json` — карты, советы,
   отрицания с якорем, числа, классы, заголовки. Это контракт того, что обязано
   выжить.
2. **Профиль и скелет.** `editor-team profiles`, затем
   `structure.py --outline <профиль>` — разделы с назначением и порядком.
3. **Образцы манеры.** `echo.py исходник.md` по разделам источника; в промпт
   шлюза они попадают автоматически через `/rules` с `depth: переплавка`.
   Образцы — STYLE ONLY: интонация, построение фраз, ритм. Факты в них про
   другие колоды и патчи.
4. **План.** JSON по схеме ниже; проверка —
   `editor-team outline validate план.json --source исходник.md --profile <профиль>`.
   `OUTLINE_INVALID` — форма и полнота, `OUTLINE_INVENTED` — карта или число,
   которых нет в исходнике.
5. **Проза по плану** в манере `ГОЛОС.md`. Заголовки — markdown `##`.
6. **Затвор.** `editor-team check результат.md --source исходник.md --profile <профиль>
   --declared-missing <id,…>` до `PASS`. Отдельно: `rewrite_gate.py результат.md`
   даёт абсолютные числа, `claims.py исходник.md --после результат.md` — покрытие.
7. **Ответ.** Текст → «Не хватает в исходнике» → «Сколько».

## Схема плана

```json
{
  "sections": [
    {"id": "builds", "title": "Сборки", "claims": ["две версии: с пиратами и с Галакрондом"]},
    {"id": "mulligan", "title": "Муллиган", "claims": ["ищите Боевой якорррь", "не оставляйте Галакронда против агро"]}
  ],
  "missing_sections": ["matchups"],
  "notes": ["в исходнике нет разбора матч-апов"]
}
```

Тезисы — только из исходника, с картами и числами как в исходнике. Каждый
обязательный раздел либо в `sections` с тезисами, либо в `missing_sections`.

## Паттерн слопа → авторская форма

| Во входе | У автора |
|---|---|
| «стоит отметить», «важно понимать» | рамка убирается, остаётся факт |
| «является», «представляет собой», «осуществляет добор» | прямая связка или глагол: «добирает» |
| «не просто X, а Y» | утверждение прямо; противопоставление только с новым фактом |
| «быстрой, надёжной и стабильной» | остаются те свойства, что есть в материале |
| «следует / рекомендуется / необходимо» | совет глаголом: «оставляйте», «не спешите» |
| «по данным HSGuru», «в выборке», «многие игроки считают» | прямой совет; в GUIDE источники за кулисами |
| «время покажет», «подведём итог» | конкретика: что делать читателю, где риск |
| эмодзи в заголовках, `**Ярлык:** пояснение` | короткие заголовки словами, связный абзац |
| одинаковая длина предложений | короткая фраза рядом с длинным периодом |
| полотно на 8+ предложений | абзац 2–3 предложения, шов по смыслу |

## Пороги затвора

Отказ стоит за краем корпуса из 49 гайдов: то, чего у автора не бывает вовсе.
Предупреждение начинается от нормы.

| Проверка | Отказ | Предупреждение |
|---|---|---|
| живой голос (`soul.py`) | < 20,6 на 1000 слов при ≥150 словах | сигнал ниже своей нижней нормы |
| ритм (`rhythm.py`) | разброс/среднее < 0,40 при ≥15 предложениях | < 0,45 |
| маркеры «убрать» | ≥ 3 | 1–2 |
| маркеры всего | > 60 на 10 000 слов при ≥300 словах | > 12,2 |
| обязательный раздел | отсутствует и не объявлен | объявлен отсутствующим |
| порядок, тонкие разделы, полотна, зачин, охват классов | — | всегда предупреждение |
| карта исходника пропала (`claims.py`) | да | раздел объявлен отсутствующим |
| совет перевёрнут, отрицание снято | да | стойка или отрицание не распознаны |
| класс исходника пропал | — | предупреждение |
| числа, коды, ОТК, возвещение | `protected_lost`, как всегда | — |

Пороги эвалов для модели строже (`tests/evals/thresholds.yaml`): от неё ждут
результата не хуже медианы автора.

## Ограничения `claims.py`

- Однословные карты («Галакронд», «Монетка») не считаются утверждениями:
  они совпадают со случайными словами. Их защищает общее правило «названия
  не трогать» и `cards.py`.
- Стойка совета распознаётся по глаголам «оставлять / сбрасывать» и их
  синонимам из `consistency.py`. Нераспознанная стойка — предупреждение, только
  распознанная противоположная — отказ.
- Отрицание проверяется по якорю (карта, класс, число) и глаголу. Если якорь
  пропал, об этом скажет проверка карт или классов, а не отрицаний.
- `declared_missing` обязан учитываться: иначе покрытие вынуждает модель
  выдумывать материал для пустого раздела.
